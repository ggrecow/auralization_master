++ 18.11.2026 - time step of the input data

BUG FIXES

- dt is estimated from the time values of all time steps (new function <get_time_step>, verification
  <validate_time_step>), used in <MASTER_auralization_EngineAirframe> and the trim functions. Before, dt was the first
  difference of the time values, which PANAM rounds to 0.1 s: with a real time step of 0.125 s, dt = 0.1 s (flyover
  played 1.25x too fast, SEL approx. 1 dB too low, Doppler shift approx. 25 % too strong with delay_line). dt is rounded
  to an integer number of samples; warning if the time values do not fit a uniform time step. The input data are not
  changed

ROBUSTNESS AND USABILITY

- the error for a non-integer fs*dt (13.11.2026) was removed: dt is now always an integer number of samples
- trim functions: the log prints dt and the actual duration of the trimmed data (before: 2*trim_time)

CHANGES IN RESULTS

- correct playback speed (with the same trim_time, the files cover the intended part of the flight); SEL, LAE and EPNL
  approx. +1 dB; smaller Doppler shift with delay_line. At 44.1 kHz with coherence loss, the decorrelation filters are
  redrawn at the block boundary after each 0.1 s mark (warning)

BREAKING CHANGES

- sampling_freq: a non-integer fs*dt no longer throws an error (see above)

++ 16.11.2026 - Doppler effect by variable delay lines (merged 18.11.2026)

NEW FEATURES

- Doppler effect by variable delay lines (optional, .ini: doppler_method, DEFAULT input = previous behaviour)
	- doppler_method = input: the sound emission predictions (e.g. PANAM) already contain the Doppler effect (as before;
	  results unchanged)
	- doppler_method = delay_line: the sound emission predictions do NOT contain the Doppler effect. The source signal is synthesized
	  in emission time, and the Doppler effect is applied separately to the direct and ground-reflected sound paths by variable
	  delay lines: each output sample at the reception time t_r reads the source signal at the emission time t_e with
	  t_r = t_e + tau(t_e), tau = propagation time of the eigenray (ray tracing). Consequences:
		- Doppler shift per path, consistent with the ray tracing (refraction, wind); before, one shift from the
		  predictions (straight sound path) was used for both paths
		- each time step of the predictions is placed at the time it reaches the receiver, i.e. at uneven intervals (closer together while
		  the aircraft approaches, further apart while it moves away), so pitch and timing at the receiver both follow from
		  the propagation times. With doppler_method = input, the steps are placed at constant intervals (timing of the
		  source) and the Doppler shift of the frequencies comes from the predictions. The .wav files are slightly shorter or
		  longer than with doppler_method = input
		- relative delay between direct and reflected path applied continuously (sub-sample), not per block in integer samples
		- propagation filters (spreading, absorption, ground reflection, HRTFs) act at the received frequencies
	- the choice is a decision of the user and must match the sound emission predictions (for PANAM: a run with or without
	  Doppler effect); it cannot be detected from the data. Predictions with Doppler effect + delay_line apply the Doppler
	  effect twice
	- convective amplification (.ini: convective_amplification, 0/1, DEFAULT 0, only used with delay_line): level change of
	  -40*log10(D) per path, D = dt_r/dt_e = 1 - M*cos(theta) from the propagation times (M = 0.25: +5.0 dB approaching,
	  -3.9 dB departing)
	- delay line: band-limited fractional-delay interpolation (Blackman-windowed sinc, 32 taps; cut-off lowered to D*fs/2 when
	  the signal is read faster than sampled, i.e. no aliasing on approach). Propagation times smoothed before differentiation
	  (local cubic fit of tau^2 over 1 s; exact for straight flight at constant speed), so that eigenray inaccuracies do not
	  cause pitch/level jitter
	- FIR filters per path (<get_FIR>): propagation delay removed from the ART transfer functions, which are converted from the
	  ART phase convention (delay = exp(+j*2*pi*f*tau)) to the MATLAB fft convention (conjugate); both paths centred with the
	  same latency. The sum of both paths keeps the magnitude of the combined ART transfer function (checked)
	- convolution blocks in reception time; each block uses the filter of the time step heard at its start
	  (<overlapp_add_convolution>: new optional input irIndex)
	- buzzsaw tones (<getTonalInput>) are not Doppler-shifted with delay_line
	- log: Doppler factor range per path, convective gain, smoothing rms, emission vs reception duration, check of the FIR
	  filter centring (warning if the direct-path peak is more than 2 samples off-centre); Doppler factor of the direct path
	  from the propagation times compared with the straight-line estimate from the input data, 1 - M*cos(phix) (+ plot *_Doppler_factor.pdf)
	- delay_line only for emission data (error otherwise); D <= 0 (supersonic towards the receiver) -> error
	- new folder auralization/doppler: get_doppler_mapping, apply_doppler_delay_line, validate_doppler_delay_line
	  (verification against analytical flyovers: level flight 300 m and 60 m, accelerating climbing departure, with and without
	  noise on tau; fractional delay accuracy < 0.01 dB up to 0.35*fs; integer delay exact). New function
	  auralization/private/get_doppler_method (reads and validates the .ini keys)

ROBUSTNESS AND USABILITY

- doppler_method (input/delay_line) and convective_amplification (0/1) are validated before the rendering
  (errors auralization:invalidDopplerMethod, auralization:invalidConvectiveAmplification)

CHANGES IN RESULTS

- doppler_method = input (DEFAULT): results unchanged (checked: bit-identical output of <apply_propagation>)

BREAKING CHANGES

- new folder auralization/doppler must be on the path (added by startup_auralization.m)

++ 14.11.2026 - HRTF angles from the arrival direction, head orientation

NEW FEATURES

- Head orientation check (binaural_signal = 1): for each receiver, the azimuth/elevation from which the direct sound
  arrives at the first and last time step, the direction the head faces and the resulting HRTF azimuth
  (front/left/back/right) are printed to the console and log.txt (new function <print_head_orientation>)

BUG FIXES

- HRTF angles now describe the direction from which each eigenray ARRIVES at the receiver (wavefront normal at the last
  ray point, new function <get_arrival_angles>). Before, the reversed launch direction at the source was used
  ([phi +- 180, theta - 90] for the direct path; launch azimuth and the straight-line elevation from the reflection
  point for the reflected path). Both are identical for straight rays (homogeneous atmosphere without wind); with
  refraction and wind (e.g. sounding atmospheres, wind profiles), the HRTFs were evaluated for the emission direction
  instead of the incidence direction. The launch angles are still used for the comparison with the PANAM emission
  angles (source directivity). The max. deviation between both directions (direct path) is printed in the log
- Reflected path, HRTF azimuth: the branch condition tested the direct ray (eigenrays(i,1).phi) instead of the reflected
  ray (eigenrays(i,2).phi). If the launch azimuths of both rays fell on different sides of 180 deg (possible below the
  flight track, y = 0, where tiny lateral components of either sign occur), no branch was executed and the HRTF angles
  of that time step stayed at [0, 0] (front, horizontal). The branch no longer exists (see above)
- Reflected path: only the elevation is smoothed (moving average, 10 time steps), no longer the azimuth. Averaging the
  azimuth mixed the 180 -> 0 deg jump at overhead (example trajectory: smoothed azimuth swept 162 -> 90 -> 18 deg within
  approx. 1 s; direction error up to 3 deg, as the elevation is close to -90 deg there) and turns a 0/360 deg wrap into
  approx. 180 deg (reflected sound from the back instead of the front). The smoothed elevation is computed as before

ROBUSTNESS AND USABILITY

- head_orientation: description corrected (behaviour unchanged). It is a fixed yaw of the head in the x-y plane of the
  PANAM coordinate system (same for all receivers, does not follow the aircraft); the HRTF azimuth is the arrival azimuth
  (0 = +x, 90 = +y) + head_orientation, i.e. the head is turned CLOCKWISE: 0 -> faces +x, 90 -> -y, 180 -> -x, 270 -> +y.
  The old description had 0 and 180 swapped (for a flight towards +x, 0 gives back -> overhead -> front and 180 gives
  front -> overhead -> back) and the facing directions of 90 and 270 swapped (the ear order given was correct). The README
  also stated that the receiver faces the sound source by default, which is not the case. The new description states
  that it assumes a flight towards +x (PANAM approach and departure) and explains flights towards -x and lateral
  receivers. Updated in the headers of <get_FIR>, <get_propagation> and <auralization_master>, both example .ini files
  and README
- head_orientation is validated (must be a number, error auralization:invalidHeadOrientation); read by the new
  function <get_head_orientation>, used by <get_FIR> and <MASTER_auralization_EngineAirframe>

CHANGES IN RESULTS

- binaural results, HRTF angles:
	- with refraction or wind (sounding atmospheres, wind profiles): arrival instead of launch direction
	- homogeneous atmosphere without wind: direct path unchanged up to the eigenray accuracy (see the max. deviation
	  printed in the log); reflected path changed only around overhead for receivers below the flight track (azimuth
	  no longer smoothed) and at time steps affected by the reflected-path branch bug
	- the meaning of head_orientation is unchanged (only its description was corrected)
	- mono results unchanged (the angles are only used for the HRTFs)

++ 13.11.2026 - DF and FF equalized binaural signals, HRIR level fix, sampling frequency check

NEW FEATURES

- Diffuse-field (DF) and free-field (FF) equalized binaural signals (optional, .ini: generate_equalized_binaural, DEFAULT 0)
	- the binaural signal is always rendered with the measured (blocked ear-canal) FABIAN HRTFs
	  (*_overallSignal_binaural_FS*.wav), for headphone playback with a measured headphone filter
	- with generate_equalized_binaural = 1, two versions of the SAME rendering are saved in addition, obtained with
	  <convert_binaural_equalization> (exact: fixed linear filters per ear, linear block convolution without output windowing):
		*_overallSignal_binaural_DFeq_FS*.wav -> HRTFs divided by the inverted, 3rd-octave smoothed, minimum-phase common
		  transfer function (CTF) of FABIAN (as AKtools 'dir' mode). For diffuse-field equalized headphones
		*_overallSignal_binaural_FFeq_FS*.wav -> HRTFs divided by the frontal HRTF (az = 0, el = 0) of the same ear, per
		  third-octave band (50 Hz - 16 kHz). For COMPUTING METRICS (LAeq, LAmax, LAE, EPNL, ECMA-418-2 'free-frontal'),
		  which already contain the outer-ear effect (the non-equalized signal would count it twice). For a frontal
		  source, FF binaural = mono within 0.1 dB (third-octave bands and LAeq)
	- the FF filter gains are set per third-octave band (iterated, so that the band energy of the equalized frontal HRTF
	  is 0 dB in every band). A bin-by-bin inversion ('exact') or a sliding 1/3-octave smoothing (as for the CTF) were
	  tested and rejected: the first turns the frontal pinna notches into narrow peaks (up to +14 dB in the 6.3 kHz band
	  for other directions), the second leaves up to 2.5 dB band errors for frontal incidence
	- the earlier option hrtf_df_equalization (DF equalization applied to the HRIRs during rendering, never released)
	  was removed; if present in the .ini, it is ignored with a console note
	- generate_equalized_binaural = 1 cannot be combined with hrtf_regularization (error)
	- new folder auralization/hrtf_equalization: get_hrtf_equalization_filter (loads DF/FF filters),
	  get_hrtf_ff_equalization (FF filter design), convert_binaural_equalization (none/DF/FF conversion of
	  binaural signals, also usable on finished .wav files), validate_hrtf_equalization (verification)
	- new file third_party/FABIAN_HRTF_DATABASE_v4/FABIAN_CTF_measured_inverted_smoothed.mat (no SOFA API needed at runtime)
	  and maintainer script utilities/convert_FABIAN_CTF_sofa2mat.m documenting how the .mat was generated
	- new file third_party/FABIAN_HRTF_DATABASE_v4/FABIAN_FF_equalization_measured_HATO_0.mat (2048-tap filters per ear)
	  and maintainer script utilities/generate_FABIAN_FF_equalization_mat.m. If the file is missing, the filters are
	  designed on the fly (warning)

BUG FIXES

- Level of the binaural signals at fs ~= 44.1 kHz: <resample> keeps the amplitude of a signal, so the resampled HRIRs had
  a frequency response scaled by fs/44100 (+0.74 dB at fs = 48 kHz, at all frequencies). The resampled HRIRs are now
  multiplied by 44100/fs. Binaural results at fs = 48 kHz are 0.74 dB lower than before; results at fs = 44.1 kHz and
  mono results are unchanged (checked: bit-identical at 44.1 kHz)

ROBUSTNESS AND USABILITY

- save_figs and generate_equalized_binaural are validated (only 0 or 1 accepted; generate_equalized_binaural before the
  rendering starts)
- sampling_freq is validated before the rendering (in <MASTER_auralization_EngineAirframe>):
	- error if fs < 44.1 kHz or not an integer (HRIRs and synthesis would lose high-frequency content)
	- error if fs*dt (PANAM time step) is not an integer number of samples (the block length is round(fs*dt),
	  so the auralized signal would drift in time)
	- console note if fs > 48 kHz (no benefit) and if binaural with fs ~= 44.1 kHz (HRIRs resampled; binaural
	  signals contain no energy above 22.05 kHz, the mono signal does)
	- recommended: 48000 Hz (DEFAULT, native rate of ECMA-418-2 and most audio hardware) or 44100 Hz

CHANGES IN RESULTS

- binaural results at fs ~= 44.1 kHz: -0.74 dB at 48 kHz (level fix of the resampled HRIRs, see above)

BREAKING CHANGES

- sampling_freq < 44100 Hz, or with a non-integer fs*dt, now throws an error
- new folder auralization/hrtf_equalization must be on the path (added by startup_auralization.m)

++ 27.10.2026 - coherence loss and changes since v1.0 (documented on this date)

NEW FEATURES

- Turbulence-induced coherence loss between the direct and ground-reflected sound (optional, .ini: consider_coherence_loss)
	- per time step, a coherence factor Ccoh(f) = exp(-w*f^2) is calculated from the atmospheric boundary layer
	  parameters (friction velocity, surface heat flux, boundary layer height, surface temperature)
	- two models available (.ini: coherence_model):
		slanted     -> Ostashev et al. (2024), JASA 156(1), 107-118, Eq. 52 (DEFAULT)
		homogeneous -> Pieren & Lincke (2022), JASA 151(4), 2453-2460, Eq. 4
	- the coherence loss is applied in <get_FIR> through random decorrelation filters, updated in fixed epochs of 0.1 s.
	  The random realizations are reproducible through .ini: coherence_seed
	- ignored (with console message) for flush-mounted receivers, as there is no second propagation path
	- new folder auralization/coherence_loss: get_abl_turbulence, get_coherence_factor_slanted,
	  get_coherence_factor_homogeneous, get_decorrelation_filter + verification routines
	  (validate_ostashev, validate_decorrelation_filter, compare_coherence_models)

- Optional HRTF high-frequency regularization (internal flag hrtf_regularization in <get_FIR>, DEFAULT 0)
	- flattens the HRTF magnitude between f1_reg = 4 kHz and f2_reg = 8 kHz, keeping the phase
	- off by default, since it removes pinna notches and high-frequency ILD (elevation/front-back cues)

- Flush-mounted receivers (zobs = 0) are now handled physically (closes #4)
	- no reflected eigenray is searched; total pressure is p_tot = p_dir*(1+Q), i.e. +6 dB for a hard ground plate
	- the previous workaround (truncating the receiver height to 1 cm) was removed. It created a spurious
	  interference notch (approx. 8.6 kHz overhead) that only existed because of the arbitrary 1 cm
	- binaural rendering is disabled with a warning for flush-mounted receivers (no head at zobs = 0)

- Cleaner plots (closes #5)
	- new .ini parameter save_figs: 0 -> only .wav files and log.txt are saved; 1 -> figures are also saved (DEFAULT)
	- new flag show_figures_on_screen (in <auralization_master>, DEFAULT 0): figures are created/saved without being
	  displayed on screen
	- if save_figs = 0 and show_figures_on_screen = 0, most figures are not created at all (faster runs)
	- .wav files are now ALWAYS written. Before, the .wav save path was tied to the figure saving

BUG FIXES

- HRIRs are resampled from 44.1 kHz (FABIAN) to the framework sampling frequency. Before, at fs = 48 kHz, all HRTF spectral
  features were shifted up by a factor fs/44100 (approx. 1.5 semitones) and all ITDs were scaled by 44100/fs
- FIR filters: direct and reflected IRs are centered to the same delay, and the original relative delay is applied to the
  reflected IR only. The sum of both IRs now matches the combined transfer function from ART. The relative delay is
  computed as the minimum signed circular distance (IRs are periodic after the IFFT). Case without ground reflection fixed
- <PLOT_spectrogram_difference> failed when mono and binaural signals had different lengths
- <create_auralization_results_folder> used hardcoded '\' separators (failed on Linux/macOS) and assumed the results path
  ends with a separator; a <results_path> without trailing separator created a wrongly named folder. Now uses <fullfile>
- unit comments of sigma_e corrected (Pa.s/m^2, not kPa.s/m^2). Values and implementation were already correct

ROBUSTNESS AND USABILITY

- .ini handling in <auralization_master>:
	- no <input_file_path> given: exactly one .ini must exist in <main_input_path>, otherwise an error is thrown
	  (auralization:noIni, auralization:ambiguousIni). Before, a warning + return ended the .exe silently without results
	- explicit <input_file_path> is checked (auralization:iniNotFound); unreadable files raise auralization:iniNotReadable
	- relative <sounding_filepath> is resolved relative to the folder of the .ini (works from any MATLAB current folder
	  and in the compiled .exe); absolute paths unchanged
	- <main_input_path> can be given with or without a trailing file separator
- show_propagation in <MASTER_auralization_EngineAirframe> now follows the <show> flag (was hardcoded to 1)
- xline/yline replaced by version-safe wrappers (xline_local, yline_local) for MATLAB <= R2018a
- example input data reorganized: flight data shared in input_data/, one subfolder (with one .ini) per example:
  example_homogeneous_atmosphere/ and example_sounding_atmosphere/ (+ atmosphere_soundings/)
- example script renamed run_auralization.m -> ex_run_auralization.m; paths built from the script location; optional
  error-case tests (run_tests)
- documentation: header of <auralization_master> (outputs, show/save options, propagation effects, binaural synthesis),
  header of <get_FIR>, .ini files and README updated

CHANGES IN RESULTS

- mono results: unchanged, except for flush-mounted receivers (differ from the old 1 cm workaround above approx. 4 kHz)
  and when coherence loss is switched on
- binaural results: change for fs ~= 44.1 kHz (resampling fix) and because the HRTF regularization is now off by default.
  The previous binaural results cannot be reproduced exactly, since they included the sampling frequency error

BREAKING CHANGES

- no .ini or more than one .ini found in <main_input_path> (and no <input_file_path> given) now throws an error
- run_auralization.m renamed to ex_run_auralization.m
- relative <sounding_filepath> is interpreted relative to the .ini folder, not MATLAB's current folder
